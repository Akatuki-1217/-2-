# 戦略RPG（MVP）

「戦闘する → 報酬で強化する → また戦闘する」の基本サイクルを、1対1のコマンドバトルで遊べるブラウザゲームです。
要件定義書 v1.1 に沿って作っています。

## 遊び方

`index.html` をブラウザで開くだけで動きます（ビルド・サーバー不要）。スマホ縦画面・PC両対応。
セーブはありません。再読み込みすると Lv1・拠点に戻ります。

| 画面 | スマホ | PC |
| --- | --- | --- |
| 拠点 | 「出撃」「本」をタップ | Enter＝出撃、Esc＝本 |
| 戦闘 | 攻撃／魔法／スキルをタップ → 一覧からタップ、「戻る」 | A＝攻撃、W＝魔法、S＝スキル、一覧は ↑↓＋Enter、Esc で閉じる |
| 敗北表示 | タップ | Enter |
| 結果画面 | 「次の戦闘へ」「拠点に戻る」 | 矢印で選んで Enter |
| 本（ステータス） | 「スキルツリー」「戻る」 | Enter＝スキルツリー、Esc＝拠点 |
| スキルツリー | スキルをタップ → 「獲得する／やめる」 | 矢印で選んで Enter、確認は ←→＋Enter、Esc で戻る |

- Tab でボタンにフォーカスを合わせた場合は、Enter でそのボタンが押されます（矢印キーの選択もフォーカスに合わせて動きます）
- A/W/S はキーの位置で判定するので、日本語入力がONでも効きます

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` / `style.css` | 画面の骨組みと見た目 |
| `data.js` | 能力値・魔法・スキル・敵・スキルツリー・成長ルール・ランク表・演出時間 |
| `validate.js` | data.js の検査（DOM非依存）：ランク表の範囲外、存在しないスキルへの参照など |
| `battle.js` | 戦闘計算（DOM非依存）：ダメージ、行動順、撃破判定、クールタイム、data の定義からの敵ユニット生成 |
| `growth.js` | 経験値・Lvアップ・スキル獲得の判定（DOM非依存） |
| `ui.js` | 画面の描画 |
| `main.js` | ゲームの状態、入力、画面遷移 |
| `tests/acceptance.test.js` | 完了条件のうち計算で確かめられるものの自動テスト |

## テスト

```sh
node tests/acceptance.test.js
```

ブラウザのコンソールからも直接呼べます（例）:

```js
// ファイアのダメージ（7）
const p = Battle.createUnit({ id: 'p', name: '主人公', side: 'ally', stats: DATA.player.stats });
const e = Battle.createUnit({ id: 'e', name: '試験兵', side: 'enemy', stats: DATA.enemies.soldier.stats });
Battle.calcDamage(p, e, { type: 'magic', power: 1.2 });   // → { damage: 7, effective: true }

// 通常攻撃だけで戦わせる（5ターンで勝利）
Battle.simulate([
  Battle.createUnit({ id: 'p', name: '主人公', side: 'ally', stats: DATA.player.stats, actions: [DATA.normalAttack] }),
  Battle.createEnemyUnit(DATA, 'soldier'),
]);

// data.js の検査（問題がなければ空の配列）
Validate.validateData(DATA);

// Lvアップの乱数を固定する
Growth.setRandom(Growth.seededRandom(42));
Growth.addExp(Game.ch, 30, DATA);
Growth.setRandom(); // 元に戻す

Game.ch // 今のキャラクターの状態
```

## 調整のしかた

数値はすべて `data.js` にあります。書き換えて再読み込みするだけで反映されます。

- 試験兵のHPを28にする：`enemies.soldier.stats.hp`
- 必要経験値をLvごとに変える：`growth.expToNext` を配列にする（例：`[30, 40, 50]`）
- スキル・魔法の値：`skills`。第7章のランク表（`ranks`）の範囲外だとコンソールに警告が出ます（テストでも検査します）
- 魔法にクールタイムを付ける：魔法の `cooldown` を1以上にすると、戦闘・一覧・確認表示にそのまま反映されます。第7章では暫定で「なし」なので、コンソールに警告は出ます
- 敵に魔法・スキルを持たせる：`enemies.soldier.actions` にスキルIDを足します。MP不足などで使える行動がないときは「様子を見ている…」（待機）で手番を終えます

## 要件で決まっていなかった点の扱い

- 試験兵のHPは要件どおり **30** のまま（未決事項）。30でも28でも、Lv1で回復せずに戦うと、攻撃とファイアをどう使っても連勝は2回までになることをテストで確認済み（各戦闘でファイアを何回使うかを総当たり）
- 本の画面からスキルツリーへのキー操作は **Enter** にしました
- スキル獲得の確認表示は「獲得する」が最初に選ばれた状態です（←→で「やめる」に切り替え）
- 押しっぱなしによるキーの連続入力は無視します（矢印キーを除く）
- スキル獲得数には、最初から持っているファイアも数えます
- 使える行動がないユニットは待機して手番を終えます（今の試験兵では起きません）

## 手動で確かめる完了条件

画面と操作にかかわる完了条件（第12章）は自動テストでは確かめにくいので、変更したら以下を手で確認します。

**戦闘**

- [ ] 攻撃・魔法・スキルのボタンを連打しても、モーションや敵の行動の間は行動が1回しか起きない
- [ ] MP不足の魔法、クールタイム中のスキルが一覧でグレー表示になり、押せない。スキルは残りターンが出る
- [ ] 初期状態のスキル一覧に「まだ覚えていません」と出る
- [ ] 戦闘ログが増えても、最新の行が見えている
- [ ] 負けると「敗北…」と経験値が0になったことが出て、タップ／Enterで拠点に戻る

**スマホ（縦画面・片手）**

- [ ] 「出撃 → 戦闘 → 結果 → 拠点 → 本 → スキルツリー → スキル獲得」を親指だけで回せる
- [ ] コマンドボタンが画面の下にあり、押しやすい大きさ（高さ44px以上）

**PC（キーボードだけ）**

- [ ] Enter で出撃 → A／W／S で戦闘 → 結果画面で矢印＋Enter → 拠点で Esc（本）→ Enter（スキルツリー）→ 矢印＋Enter → 確認で ←→＋Enter、の1サイクルを回せる
- [ ] 日本語入力をONにしたままでも A／W／S が効く
- [ ] Tab で「拠点に戻る」「やめる」「本」に合わせて Enter を押すと、そのボタンが押される（別のボタンが押されない）
- [ ] 確認表示が開いている間、Tab で後ろのボタンに移らない
